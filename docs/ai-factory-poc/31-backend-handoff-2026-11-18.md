## Review pagination and Agent units

On November 19, PR #5927 targeted `bootcamp-prototype` for the following changes.

- **Review** requests `GET /tms/test-case?filter.eq.iterationId=<iterationId>&offset=<offset>&limit=25`. The filter uses the numeric iteration ID, and `page.totalElements` determines pagination. Each row opens the case by its returned numeric ID. Fix Trace loads history on demand for the selected case and keeps rounds whose `previousIterationId` matches the source iteration. Use **Refresh** in the Review list while the iteration is active. [Review request](../../app/src/pages/inside/aiFactory/iterationDetailsPage/liveReviewCases/liveLibraryCases.ts) · [Fix Trace loader at e00880716](https://github.com/reportportal/service-ui/blob/e00880716a498a78556eaa4ba8b41d7d5360b2c1/app/src/pages/inside/aiFactory/iterationDetailsPage/generationReviewTraceChooser/loadGenerationReviewRounds.ts)
- **Agent units** formats `DURATION` values from milliseconds and groups `NUMBER` values by locale. The table and Stage Trace prefer a nonblank `cells.name`, then `cells.unit`, then `row.key`. Trace labels use the selected attempt snapshot. Event matching uses `event.unitKey === row.key`, so units with identical names remain distinct. [Unit name helper](../../app/src/common/utils/agentUnitName.ts)
- **Verification** on source commit `e00880716` includes 1,370 local tests, TypeScript, changed-file ESLint, GitHub Node 20 Build and the SonarCloud Quality Gate. The November 19 public OpenAPI advertises the iteration filter in TMS `feature-pipelines-2935` at backend revision `7e5b4a4add0af4cdc1a36447b539ed10b89d93c3`. Authenticated Review pagination and Agent units from a real producer still need verification with the frontend deployed and development mocks disabled.
